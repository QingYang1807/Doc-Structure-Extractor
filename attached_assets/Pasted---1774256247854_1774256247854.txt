## 二、技术方案对照表

| 难点         | 典型表现             | 技术方案                               | 可选模型/方法                                   | 落地风险          | 评估指标               |
| ---------- | ---------------- | ---------------------------------- | ----------------------------------------- | ------------- | ------------------ |
| 扫描质量差      | 倾斜、模糊、噪点、阴影      | 图像增强、去噪、校正、分页修复                    | OpenCV、PaddleOCR预处理、自研图像管线                | 前处理过强会伤字形     | OCR字准率、页可读率        |
| 复杂版式       | 双栏、脚注、页眉页脚干扰     | 版面检测 + 阅读顺序重建                      | LayoutLM、DocLayout、PaddleOCR PP-Structure | 顺序错了会连锁出错     | 版面块检测准确率、阅读顺序准确率   |
| OCR误识别     | 数字、专有名词、印章旁文本识别错 | 通用OCR + 领域词典纠错 + LLM修复             | PaddleOCR、TrOCR、Qwen-VL类能力                | LLM纠错可能“改错”原文 | CER、WER、关键字段准确率    |
| 标题层级混乱     | 章节、条款、附件关系不清     | 基于编号规则 + 布局特征 + 语义分类建树             | 正则规则、分类模型、LLM结构恢复                         | 不同模板差异大       | 章节树准确率             |
| 跨页表格       | 表头在前页，数据在后页      | 表格检测 + 表头继承 + 跨页拼接                 | Table Transformer、PP-Structure、规则拼接       | 容易把两张表错拼      | 表格还原率、单元格映射准确率     |
| 合并单元格/无边框表 | 字看见了，结构没还原       | 基于坐标聚类 + 行列推断 + 语义补齐               | CV表格检测 + 几何规则 + LLM校正                     | LLM容易补出不存在的列  | TEDS、单元格F1         |
| 图表理解       | 柱状图、流程图、组织图      | 元素检测 + OCR + 图形关系解析 + 文本摘要         | 多模态模型、图表理解模型                              | 图表语义容易丢失      | 图表问答准确率            |
| 印章识别       | 公章、骑缝章、电子章       | 目标检测 + 分类 + 位置关联                   | YOLO类检测、OCR、规则引擎                          | 真伪识别难度更高      | 检测召回率、章位合规率        |
| 手写批注       | 圈画、删改、手写备注       | 手写OCR + 批注区域检测 + 挂接正文              | 手写识别模型、多模态LLM                             | 中文手写稳定性波动大    | 批注识别率、批注挂接准确率      |
| 字段抽取       | 甲乙方、日期、金额、账号     | 模板抽取 + NER + LLM schema extraction | BiLSTM-CRF/BERT-CRF、LLM函数调用               | 字段定义经常变       | 字段准确率、召回率          |
| 条款抽取       | 违约责任、解除条件、保密义务   | 条款级切分 + 分类 + span抽取                | 法律文本分类模型、LLM抽取                            | 条款边界不稳定       | 条款识别F1             |
| 关系抽取       | 引用、约束、优先级、例外关系   | 关系抽取 + 图谱构建 + 引用链回溯                | RE模型、图数据库、LLM关系归纳                         | 关系错比漏更危险      | 关系F1、引用链正确率        |
| 补充协议覆盖原合同  | 多版本冲突            | 文档级版本链管理 + 优先级规则 + 冲突检测            | 规则引擎 + LLM比对                              | 业务规则极其复杂      | 冲突发现率、最终结论一致率      |
| RAG召回不准    | 问答时找不到关键条款       | 条款级chunk + 表格块chunk + 混合检索         | BM25 + 向量检索 + rerank                      | 切片不当会毁掉效果     | Recall@K、MRR、证据命中率 |
| 多跳推理       | 需要结合正文、附件、表格一起回答 | 检索链 + 推理链 + 中间状态保存                 | ReAct、Graph RAG、工作流编排                     | 容易推偏或遗漏约束     | 最终问答准确率、证据完整率      |
| 幻觉         | 模型补结论、补字段        | 强制引用、答案约束、原文回查                     | JSON schema、引用约束、Verifier                 | 纯Prompt控制不稳   | 幻觉率、引用一致率          |
| 业务可审计      | 用户问“依据在哪”        | 页码定位、原文高亮、证据链输出                    | 坐标索引、trace链路                              | 没坐标就很难补       | 可追溯率、人工复核通过率       |
| 性能与成本      | 大文档慢、并发低         | 异步解析、分阶段缓存、轻重模型分流                  | OCR服务化、队列、缓存、批处理                          | 成本压不住会很难商用    | 单页耗时、单文档成本         |
| 安全合规       | 合同/政策很敏感         | 权限隔离、脱敏、日志审计、本地部署                  | IAM、脱敏规则、私有化LLM                           | 云侧模型合规受限      | 脱敏准确率、审计完整率        |

## 五、评估指标建议

很多团队做文档处理，最大的问题不是模型不强，是**没评估体系**。
建议你直接拆成这几类指标。

| 指标类别 | 指标项                     | 含义           |
| ---- | ----------------------- | ------------ |
| 识别指标 | CER / WER               | OCR字词错误率     |
| 结构指标 | 章节树准确率、表格还原率            | 版式恢复是否正确     |
| 抽取指标 | Precision / Recall / F1 | 字段和条款抽取效果    |
| 检索指标 | Recall@K、命中率            | RAG能不能找到正确证据 |
| 推理指标 | 问答准确率、证据完整率             | 回答是否对、证据是否全  |
| 工程指标 | 单页耗时、单文档耗时、并发量          | 能不能上线跑批      |
| 业务指标 | 人工复核通过率、审核节省时长          | 对业务有没有价值     |
| 风险指标 | 幻觉率、冲突漏检率               | 结果靠不靠谱       |

## 六、最现实的落地建议

你如果是做 **最小可用产品**，建议先盯住这条链：

**PDF/图片上传 → OCR/版面分析 → 条款切分 → 表格提取 → 字段抽取 → 证据问答 → 风险报告**

先别一上来就碰太重的：

* 图表复杂理解
* 全量知识图谱
* 手写批注全场景支持
* 超长链多跳自动推理

这些都能做，但第一版很容易把自己拖死。

## 七、给你一个更适合汇报或方案里的总结表达

你可以直接放进方案文档里：

> 文档提取的核心挑战，不在于单点识别，而在于复杂文档中多模态信息的统一理解、结构恢复、语义抽取、证据定位与业务可审计输出。
> 在法律合同、政策法规等高复杂场景下，系统需要同时处理复杂版式、跨页表格、条款引用、版本冲突、印章批注、多跳推理等问题，最终将非结构化文档转化为可计算、可检索、可推理、可追溯的结构化知识资产。
